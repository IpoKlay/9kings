Change
The previous square atlas changed horizontal texture-coordinate normalization and produced edge-pixel differences at fractional unit scales. Packing sheets vertically with their original widths (1088 or 64) and power-of-two heights eliminated differences in the tested renders. The new layout keeps complete sheets, all original frame indices, foot anchors, animation selection, source rectangles and painter order. It does not rotate or trim assets.
96 sheets use eight pages; maximum page height8192, uncompressed RGBA8 pages total 157.50 MiB. This trades some padding memory for identical sampling, not a memory-saving claim.
Each page has a white texel in a separate unused row. A soldier's two shadow rectangles now sample that texel from the same page as the soldier, using their original geometry and colors. Shadows remain immediately before their soldier in the original foot-y-sorted order. Corpse rendering, effects, game rules and input handlers are unchanged.
The HUD uses a shared atlas and background drawing on its existing controls; input, text and focus remain on those controls.

Validation
- Exported macOS PCK: all 96 sheets and shadows loaded; normal menu-to-battle entry passed in a headless runtime. Both export presets explicitly include the atlas JSON manifest. This is a resource-pack smoke test, not a standalone app playthrough.
- Source image RGBA round trips: 96 sheets, no rotation or trimming.
- Sampling fixture: all directions and animation cells, alternating full-body and split-body drawing, five scales plus a rotated pose (576 cases), zero pixel differences using imported textures. See tests/tactical/test_unit_atlas_sampling.gd.
- Whole battle: 13 before/after captures across three camera zooms, movement/contact/attacks/casualties through1200 simulation steps, and petrification. All pixel-identical on the tested branch.
- Chinese HUD input and visual regression: zero failures,16 state comparisons plus a first-rendered-frame hover check.
- Command-route input regression: 27 checks, zero failures. Godot reported four ObjectDB instances and two resources retained at exit; this remains a cleanup warning.
- The root-window performance fixture checks equal final positions, health and morale between native and atlas runs.
An early insufficiently settled capture had a one-pixel discrepancy and an out-of-date petrification frame; the final fixed-seed fixture uses six settled rendered frames per capture. Initial results were not used as passing evidence.
