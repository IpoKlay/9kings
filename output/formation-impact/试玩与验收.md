# 六排冲锋试玩与验收

GitHub 同步说明：此目录上传了六排完整源码与验收证据。下文的 `.app` 为已交付的本机包，不在 Git 源码历史中；下载仓库后请用 Godot 4.7.2 打开「六排Godot工程/project.godot」运行。

从本目录打开「鹰旗之下·六排冲锋.app」，进入「军团会战 · RTS」→「七兵种布阵」→「开战」。英文界面对应 Legion Battle · RTS → All seven arms → Begin。战中左键选队、Shift 添加路点、左键确定终点、右键敌队集火，空格暂停或继续。选择暴露侧翼，给骑兵留出直线助跑距离。主工程继续使用单排；本目录的「六排Godot工程」可以独立打开，应用标识及试玩设置目录也独立。

## 实机镜头

1. [静音侧冲](after-flank.mp4)。默认 15% 阵宽、固定镜头、正常速度、无血条与冲击粒子。红方从画面左下向右上切入蓝方靠左下的阵角。[原始分辨率逐帧截图](关键帧/) 和 [侧冲图序](flank-关键帧.png)。
2. [同条件并排标注](侧冲与迎击-带标注.mp4)。两支满编对照单位分别为普通军团步兵和已经面向骑兵坚守的长矛兵。同一骑兵编制、起点、命令时刻、目标中心与镜头。黄色小框标记首次冲击结束时领骑脚点，随后仍会发生普通近战。保留了[用户辨认时的原始静音对照](盲评原片.mp4)。
3. [错位盾墙](after-wall.mp4)。两阵初始横向错开 112 场地像素，进攻方沿原轴推进。约 7.97 秒首次交手；8.45 秒观察接触带，左侧外翼仍向前，重叠的几列停在对面盾前。[盾墙图序](wall-关键帧.png)。
4. [正式七兵种会战](七兵种会战.mp4)。主菜单进入山口，七兵种布阵，暂停、选骑兵、Shift 加路点、下达终点、恢复；20 秒战斗时间投入预备骑兵，再次暂停并指向敌军侧面。战斗计时 25.67 秒首次侧冲，83.30 秒另一次侧冲。全局记录盾墙接敌、47 次治疗、45 次石弹落地，96.22 秒敌军溃退。片头及暂停操作占用额外录像时间，第一次侧冲约在视频 29 秒。重试后回部署状态，冲锋编号、局部偏移、活动投射物、效果清空；所属撞击声道在重试时停止。
5. [改前与改后，同步侧冲](侧冲改前改后.mp4)，左为本轮改前，右为六排交付版。另存了每种情形的 before、after 单段录像。所有战斗画面由 Godot 会战渲染，逐帧图为实机画面裁切。

## 接触和通行量测

追踪从第 0 帧计数，30 Hz 画面每帧推进两个固定模拟步。场地像素为投影平面、镜头缩放前的单位。

| 指标 | 斜撞军团侧翼 | 正冲坚守长矛 |
|---|---:|---:|
| 首次接触，在 30 Hz 追踪中首次显示 | 第 101 帧，3.40 秒 | 第 102 帧，3.43 秒 |
| 接触速度（世界单位/秒） | 252.98 | 252.98 |
| 首击伤害次数及数值 | 1 次，71.4 | 1 次，17 |
| 首轮通道前缘实际行进距离 | 114 px | 7 px |
| 领骑脚点沿入射轴净前移，冲击结束瞬间 | 113.9 px | 0.3 px |
| 整队中心沿入射轴净前移 | 47.9 px | 2.9 px |
| 距冲击结束 0.32 秒内的局部响应 | 14 个槽位越过 4 px 位移阈值，横向覆盖约 54 px | 2 个槽位收到接触，1 个越过 4 px 阈值 |
| 穿入列数 | 折算约 4.5 个列距，经过第 1 至第 5 列的槽位 | 未穿过第一列 |

列距按 26 px、排距 16 px、每排横向错列 5 px，以领骑沿投影入射轴的位移换算。响应宽度按受影响脚点在入射轴法向上的跨度计算。没有把士兵精灵的宽度或地表粒子额外算进冲击带。

30、60、120 Hz 分别运行真实会战更新。三档均只结算一次首击，两组结果在模拟时钟上分别首次显示于 3.40 和 3.433 秒。三个帧率下冲击结束后的方阵中心分别一致，为投影坐标 (1795.38,956.27) 和 (1760.26,977.76)。显示采样可相差一个画面帧。逐档原始数据在 flank-30/60/120.jsonl 和 pikes-30/60/120.jsonl，领骑脚点见两份 depth.jsonl。

## 反馈与参数

骑兵继续前推时查询偏移后的步兵脚点，外侧士兵错开，后续骑手分别检查自己前方的通路。石障、战场边缘与狭门排队可截停位移。击退和补线只影响槽位；生命、寻路、士气、溃逃仍归方阵结算。声效使用接近时的马蹄、一次主撞击和稀疏尾音。箭群在拉弓后飞往目标局部位置，石弹沿既有飞行时间落下，军医提示显示在获治疗的友军上。

可在六排工程的 data/balance/tactical_trial.json 调整以下值。

| 参数 | 当前值 | 用途 |
|---|---:|---|
| lane_half_width | 29 px | 冲击带半宽，越靠外位移越小 |
| flank_spread | 26 px | 侧击中心最大横向让位，约一个兵位 |
| flank_depth / front_depth / braced_depth | 114 / 22 / 7 px | 侧击、正面、坚守长矛三种情形的穿入上限，实际还受阻力和空位约束 |
| gap_hold | 1.0 秒 | 每个槽位自受击起维持缺口的时间，随后约 0.56 秒走回 |
| top_speed / sprint_seconds | 1.82 倍 / 0.52 秒 | 沿用的冲锋峰值与加速时长 |

单队和三队音频分别为 [一队](mix-1.m4a)、[三队](mix-3.m4a)。三队在同一模拟步命中，日志记录三次战斗命中、一次主要撞击起音。两份音频解码后单声道峰值均约 −5.96 dBFS。用户盲看确认“左边撞开，右边拦住”，试听确认“主撞击清楚”。具体列号来自槽位追踪。最后一次视觉微调让步兵在缺口保持期间站稳，并在归位时转身迈步；此微调后的恢复动作由实机逐帧检查。

## 回归与性能

实测了两队同时冲同一队、重复接触记录去重、改令取消余速、目标提前死亡、暂停、半速、转向后重新列矛、石障和场地边缘截停、排队中的士兵不能挤入狭门。原生路点、旗区与山口遭遇测试也已复测。原关卡的坚守、诱敌与撤防三套打法均能结束。交付包通过 Mac 签名校验，从包内资源完整运行至会战结算并重试。主工程单排检查另见 main-single-rank.log。

同一台 Apple M4、同一高负载七兵种编制（592 个可见兵员/器械）、同一镜头和预热流程。两次独立运行，每次采样 300 帧，大小 854×480；从模拟推进计到 GPU 图像回读，包含读回成本。此数据用于比较本轮开销。

| 版本 | 平均帧耗时，两次 | 第 95 百分位，两次 |
|---|---|---|
| 改前六排 | 4.95 / 4.80 ms | 6.03 / 5.96 ms |
| 六排冲锋版 | 5.70 / 5.75 ms | 6.62 / 6.61 ms |

静音侧冲和长矛拦停已能清楚区分。侧冲录像 4.43–5.35 秒，领骑深入之后的收队还有偏整齐、偏滑的观感，尤其是几匹马回到队列的速度相近。远景下细小的盾面碎屑较难逐个辨认。性能证据限于本机、上述编制和分辨率。无窗口快速退出时，改前与导出版都记录了菜单音乐 the-pyre.mp3 的资源释放提示，启动进程退出码为 0。

六排源码在「六排Godot工程」，单排到六排的文本差异见「单排到六排.patch」。复测脚本与原始日志保存在本目录。六排和单排的应用标识及设置目录各自独立。
