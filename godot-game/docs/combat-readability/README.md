# 冲锋与阵形辨识：2026-11-09

范围：常规野战的实际站位、局部接触、穿入/受阻、接战与重试。不开发千人或攻城；保留 main 的经济开局、编队和镜头更新。

## 已确认的验收条件

用户确认 Apple M4 / 16 GB Mac，输出 1280×720，固定七兵种 114 名实际士兵，峰值不扩人数；60 FPS，p95 帧耗时 ≤20ms，>50ms 卡顿每分钟 ≤1次，操作反馈 ≤100ms。受控普通野战仍用已有 114 人配置；最新正式入口为 6 村民经济开局，两者不混称。

画面保持现有 64×64、八方向、脚点及单位尺寸。没有新增美术、纹理或常驻图集；战场内部仍按既有 960×540 子视口绘制，最终输出单独核对真实图像像素。不得把逻辑布局 1920×1080 当作实际渲染输出。

## 测量与工程约束

- 固定基础版本 bbe557b、同一设备/输出/相机/114人/种子，顺序执行修改前后可见窗口测试。60 FPS 上限；请求启用垂直同步，但驱动实际报告为关闭（两次均为 0）；不用 MovieMaker 或手动推进充当实时性能。
- 帧间隔用正常主循环单调时钟测量；记录均值、p95、>50ms 次数及每分钟频率。CPU 用 Performance.TIME_PROCESS 辅助定位；不以 CPU 指标代替总帧耗时。
- GL Compatibility 渲染器的独立 GPU 毫秒数未取得，不宣称 GPU 单项预算通过。记录纹理驻留监视值、静态内存及外部进程 RSS；这些不等于整个 GPU 显存。资源加载记录正常入口耗时，不做逐帧加载。
- 输入由引擎输入事件发送并等待实际呈现帧测量；与系统鼠标实玩分别标注。CPU/GPU/内存/加载单项硬预算尚未单独确认，不能代替已确认的帧时间与反馈目标。
- 保留原有逐人更新、选敌/寻路频率与空间邻居索引。冲锋阻力复用已有接触遍历；仅离槽的盾墙成员在缺口保持结束后最多每 0.2 秒检查返回路径是否被活敌人占据，最坏 O(离槽人数×活人数)，在 114 人场景测量。没有新增全员每帧寻路或资源复制。

## 实现

- 盾墙拖拽宽度按实际人数分配列数，不再产生额外的空列、把士兵压进中央；物理脚点、选择、渲染、碰撞均读同一站位。
- 每位受击者根据自己的朝向、移动速度、是否完成阵型、举盾/持矛判断阻力。移动、侧击和正在组阵的长矛不享受静止正面迎击。
- 骑兵独立记录接触与有限余势。侧击产生局部横向错步；正面盾墙受压退步；长矛短退，骑兵停止冲锋、短促收步后进入原有近战。
- 一匹马对同一受击者只结算一次冲锋；伤害公式仍沿用既有规则，冲锋速度变化自然影响速度系数。此处是本项目的新阻力设计，不是已证明与原作相同。
- 缺口保持至少 2.6 秒；活敌人仍占据返回路径时继续在当地接战。归队沿现有地形路径走回，不传送。新命令可取消骑兵短暂收步。
- 接触姿态读取每个骑手的真实接触时刻；受击者完整身体姿态不再被独立上身图层遮住。没有全局停顿或镜头震动。
