# 音频退出引用修复

## 问题与处理

基线 `982f314` 在菜单快速退出时留下 `the-pyre.mp3` 及其播放对象；策略界面退出时还可能留下 `crusade.mp3`。详细日志显示的是 `AudioStreamMP3` / `AudioStreamPlaybackMP3`，不是被归档的美术资源。

已有 `_exit_tree()` 会停止播放器、清空 stream 和缓存，但此时主循环已接近结束，音频服务还未完成延迟释放。这与 [Godot #76745](https://github.com/godotengine/godot/issues/76745) 的退出问题一致；仅清空缓存不能完成服务端引用回收。

主窗口关闭现在经过 `request_quit()`：停止场景处理、停止本场景及活动战场中的播放器，清空音乐缓存，再观察播放对象的弱引用。确认它们释放后才退出；等待约一秒仍未释放则明确报告超时，不无限挂起。重复关闭请求不会提前跳过等待。

音乐 `shutdown()` 同时禁用音乐更新并清空曲目缓存，防止晚到的战场关闭回调重新启动音乐。音乐资源、音量设置、正常交叉淡入淡出和战斗逻辑没有替换。清理仅在退出时执行，不增加正常游戏的逐帧遍历。

需要销毁整个游戏实例的测试先 `await app.prepare_shutdown()`，再释放节点。已更新当前策略 UI、旧攻城和音乐集成测试的结束流程。

## 验证

本机 macOS / Godot 4.7.2，基线菜单退出有 2 个对象 / 1 个资源警告，策略 UI 退出有 4 个对象 / 2 个资源警告。

- 无窗口菜单关闭、交叉淡入淡出中的战场关闭、重复关闭请求：退出码 0，无警告或错误。
- 连续三次创建、切换音乐、销毁游戏：18 项检查通过，弱引用确认播放对象实际释放，晚到的切歌请求不会重启音乐。
- 原生窗口 + CoreAudio 再跑上述三种退出场景：全部通过，无退出警告。窗口关闭信号由脚本发送，不是系统鼠标实玩。
- 当前策略 UI：27 项通过；旧攻城：29 项通过；两者退出日志无资源引用警告。
- 原音乐集成测试使用 CoreAudio：77 项通过，实际捕获约 55.59 秒音频，峰值约 0.213；验证音量、暂停、音乐切换、循环与混音输出，退出无警告。

可复现的检查命令（先完成 Godot 资源导入）：

```sh
python3 godot-game/tests/check_audio_shutdown.py --godot /path/to/Godot
python3 godot-game/tests/check_audio_shutdown.py --godot /path/to/Godot --audio-driver CoreAudio --display
```

Python 检查器同时检查退出码和进程结束后的日志，因为 Godot 有资源引用警告时仍可能返回 0。原始证据保留在本机 `output/exit-resource-fix-2026-11-11/`，新检查器日志写入 `output/audio-shutdown/`。

## 范围

这是正常退出流程的修复，不是引擎补丁。`--quit-after`、旧脚本直接调用 `SceneTree.quit()` 或强制终止进程可以绕过准备阶段，仍可能出现引擎退出警告；验证正常关闭应使用上面的测试入口。没有屏蔽警告、在无窗口模式禁播音乐或更换音频素材。

未做性能测试、Windows 验收或整局人工试玩。
